## #A06 · 如何在git分支上删除一个文件

> 🕒 2025-08-24 21:30 ｜ 来源：[链接 A](https://chat.deepseek.com/share/671qft5gcto6itzzkw) 第 6 轮（消息 ID 11–12） ｜ 主题：分支的创建与删除、丢弃工作区改动、删除文件

**提问**

如何在git分支上删除一个文件

**回答**

在 Git 分支中删除文件有几种方法，以下是详细的步骤：

#### 方法一：使用 `git rm` 命令（推荐）

```bash
# 1. 确保你在正确的分支上
git checkout <分支名>

# 2. 删除文件并暂存删除操作
git rm <文件名>

# 3. 提交删除操作
git commit -m "删除 <文件名>"

# 4. 推送到远程仓库（可选）
git push origin <分支名>
```

**示例：**
```bash
git checkout personal-changes
git rm unwanted_file.txt
git commit -m "删除不需要的 unwanted_file.txt"
git push origin personal-changes
```

#### 方法二：先手动删除文件，然后使用 Git 命令

```bash
# 1. 手动删除文件
rm <文件名>

# 2. 将删除操作添加到暂存区
git add <文件名>  # 或者使用 git add .

# 3. 提交删除操作
git commit -m "删除 <文件名>"

# 4. 推送到远程仓库
git push origin <分支名>
```

**示例：**
```bash
git checkout personal-changes
rm unwanted_file.txt
git add unwanted_file.txt
git commit -m "删除不需要的 unwanted_file.txt"
git push origin personal-changes
```

#### 方法三：删除目录（递归删除）

```bash
# 删除整个目录及其内容
git rm -r <目录名>
git commit -m "删除 <目录名> 目录"
git push origin <分支名>
```

#### 方法四：只从 Git 中删除，但保留本地文件

```bash
# 从 Git 跟踪中删除，但保留本地文件
git rm --cached <文件名>
git commit -m "停止跟踪 <文件名>"
git push origin <分支名>
```

**适用场景：** 当你忘记将文件添加到 `.gitignore`，但还想在本地保留该文件时。

#### 实际示例：

假设你要在 `personal-changes` 分支上删除 `temp.txt` 文件：

```bash
# 切换到目标分支
git checkout personal-changes

# 检查当前状态
git status

# 删除文件
git rm temp.txt

# 查看状态确认
git status  # 应该显示删除的文件已暂存

# 提交更改
git commit -m "删除临时文件 temp.txt"

# 推送到远程
git push origin personal-changes
```

#### 重要注意事项：

1. **确认分支**：确保你在正确的分支上操作
2. **备份重要文件**：删除前确认文件不再需要
3. **查看状态**：使用 `git status` 确认操作是否正确
4. **撤销删除**：如果误删，可以使用 `git restore <文件名>` 恢复

#### 撤销删除操作：

如果误删了文件，可以恢复：
```bash
# 恢复最新提交中的文件
git restore <文件名>

# 或者从暂存区撤销删除
git reset HEAD <文件名>
git checkout -- <文件名>
```

选择适合你需求的方法即可！推荐使用 **方法一**，因为它是最直接和清晰的删除方式。

## #B09 · 我在拉下来的branch中做了一些修改，但是我想不要这些修改，怎么办？

> 🕒 2026-07-10 10:30 ｜ 来源：[链接 B](https://chat.deepseek.com/share/vb9gzt7w14wkwxmurf) 第 9 轮（消息 ID 17–18） ｜ 主题：分支的创建与删除、丢弃工作区改动、删除文件

**提问**

我在拉下来的branch中做了一些修改，但是我想不要这些修改，怎么办？

**回答**

在拉取下来的分支中做了一些修改但不想要了，有几种方法可以恢复。根据你的具体情况选择合适的方法：

---

#### 方法一：丢弃所有未提交的修改（最简单）

##### 如果你还没有 `git add` 或 `git commit`
```bash
# 丢弃所有工作目录的修改
git checkout -- .

# 或者丢弃特定文件的修改
git checkout -- filename.py

# 查看哪些文件被修改了
git status
```

##### 如果你已经 `git add` 了（暂存区）
```bash
# 取消暂存所有文件（但保留修改）
git reset HEAD .

# 然后再丢弃修改
git checkout -- .
```

##### 一键丢弃所有修改（包括已暂存的）
```bash
# 重置到当前分支的最新提交，丢弃所有修改
git reset --hard HEAD

# 或者重置到远程分支的状态
git reset --hard origin/pr-10-test
```

---

#### 方法二：如果已经提交了，但还没合并

##### 情况 A：还没有推送到远程
```bash
# 1. 查看提交历史，找到想回到的提交
git log --oneline

# 2. 硬重置到上一个提交（丢弃最后一次提交）
git reset --hard HEAD~1

# 3. 或者重置到指定的提交
git reset --hard abc1234  # abc1234 是目标提交的哈希值
```

##### 情况 B：已经推送到远程（但还没合并到 main）
```bash
# 1. 重置到远程分支的状态
git reset --hard origin/pr-10-test

# 2. 或者强制推送覆盖远程（小心使用）
git reset --hard HEAD~1  # 本地回退
git push origin pr-10-test --force-with-lease  # 强制推送到远程
```

---

#### 方法三：回到 PR 最初拉取时的状态

##### 如果使用 `gh` 拉取的
```bash
# 重新拉取 PR，覆盖本地修改
gh pr checkout 10 --force
```

##### 如果使用 `git fetch` 拉取的
```bash
# 1. 重新获取 PR 的原始状态
git fetch origin pull/10/head

# 2. 硬重置到该提交
git reset --hard FETCH_HEAD
```

##### 如果拉取的是分支
```bash
# 重置到远程分支的最新状态
git fetch origin pr-10-test
git reset --hard origin/pr-10-test
```

---

#### 方法四：完全删除分支重新拉取（最彻底）

```bash
# 1. 切换到 main 分支
git checkout main

# 2. 删除本地测试分支
git branch -D pr-10-test  # 注意用 -D 强制删除

# 3. 重新拉取 PR
git fetch origin pull/10/head:pr-10-test
git checkout pr-10-test
```

---

#### 快速参考：根据状态选择命令

| 当前状态 | 推荐命令 | 说明 |
|---------|---------|------|
| **只修改了文件，未 add** | `git checkout -- .` | 丢弃所有工作区修改 |
| **已 add，未 commit** | `git reset --hard HEAD` | 重置到最新提交 |
| **已 commit，未 push** | `git reset --hard HEAD~1` | 回退一个提交 |
| **已 push** | `git reset --hard origin/pr-10-test` | 重置到远程状态 |
| **想完全重新拉取** | `git branch -D pr-10-test` + 重新 fetch | 最彻底 |

---

#### 实际操作示例

##### 示例 1：刚修改了文件，想放弃
```bash
# 查看状态
$ git status
On branch pr-10-test
Changes not staged for commit:
  modified:   file1.py
  modified:   file2.py

# 丢弃所有修改
$ git checkout -- .
$ git status
On branch pr-10-test
nothing to commit, working tree clean
```

##### 示例 2：已经提交了，想回到拉取时的状态
```bash
# 查看提交历史
$ git log --oneline
def5678 (HEAD -> pr-10-test) 我的额外修改  ← 不想要这个
abc1234 PR 原始提交  ← 想回到这里

# 硬重置到 PR 原始提交
$ git reset --hard abc1234
HEAD is now at abc1234 PR 原始提交
```

##### 示例 3：已经推送到远程了，想撤销
```bash
# 1. 本地回退
$ git reset --hard HEAD~1

# 2. 强制推送覆盖远程
$ git push origin pr-10-test --force-with-lease

# 3. 验证
$ git log --oneline
abc1234 (HEAD -> pr-10-test, origin/pr-10-test) PR 原始提交
```

---

#### 重要提醒

##### ⚠️ `git reset --hard` 会永久删除修改
- 无法恢复（除非有备份或 reflog）
- 如果你不确定，先用 `git stash` 保存修改

##### 安全做法：先用 stash 保存
```bash
# 保存当前修改
git stash push -m "临时保存我的修改"

# 然后可以安全地重置
git reset --hard origin/pr-10-test

# 如果之后想恢复修改
git stash pop
```

##### 查看 reflog 恢复（如果不小心删除了）
```bash
# 查看所有操作历史
git reflog

# 找到你想要恢复的提交
# 然后创建分支指向它
git checkout -b recover-branch abc1234
```

---

#### 最推荐的安全流程

```bash
# 1. 先保存当前修改（以防万一）
git stash

# 2. 重置到 PR 原始状态
git reset --hard origin/pr-10-test  # 或者使用 FETCH_HEAD

# 3. 确认恢复成功
git status  # 应该是 clean
git log --oneline -3

# 4. 如果确定不需要 stash 的修改了
git stash drop  # 删除 stash

# 如果还需要，可以恢复
git stash pop
```

---

#### 总结

根据你的具体情况：

| 你的情况 | 最快命令 |
|---------|---------|
| **还没 add/commit** | `git checkout -- .` |
| **已经 add 了** | `git reset --hard HEAD` |
| **已经 commit 了** | `git reset --hard HEAD~1` |
| **已经 push 了** | `git reset --hard origin/pr-10-test` |
| **想完全重新拉取** | `git branch -D pr-10-test` 然后重新 fetch |

**最安全的方式**是先 `git stash` 保存修改，然后重置。确定不需要了再 `git stash drop`。

## #B15 · 在branch上修改了app.py，如何删除这个修改？

> 🕒 2026-07-11 20:22 ｜ 来源：[链接 B](https://chat.deepseek.com/share/vb9gzt7w14wkwxmurf) 第 15 轮（消息 ID 29–30） ｜ 主题：分支的创建与删除、丢弃工作区改动、删除文件

**提问**

在branch上修改了app.py，如何删除这个修改？

**回答**

在分支上修改了 `app.py` 文件，想要删除这个修改，有几种方法，取决于修改的状态：

---

#### 方法一：如果还没有 `git add`（修改在工作区）

```bash
# 丢弃 app.py 的修改，恢复到最近一次提交的状态
git checkout -- app.py

# 或者使用 restore（Git 2.23+）
git restore app.py
```

**验证：**
```bash
git status
# 应该显示：nothing to commit, working tree clean
```

---

#### 方法二：如果已经 `git add` 了（修改在暂存区）

##### 步骤 1：取消暂存
```bash
# 从暂存区移除，但保留修改
git reset HEAD app.py

# 或者使用 restore（Git 2.23+）
git restore --staged app.py
```

##### 步骤 2：丢弃修改
```bash
# 现在修改回到了工作区，再丢弃
git checkout -- app.py

# 或一步到位（取消暂存并丢弃修改）
git checkout HEAD -- app.py
```

**一步完成：**
```bash
# 直接恢复到 HEAD 状态（丢弃暂存和工作区的修改）
git restore --staged --worktree app.py
# 或
git checkout HEAD -- app.py
```

---

#### 方法三：如果已经 `git commit` 了（但还没推送）

##### 情况 A：撤回最后一次提交（保留修改）
```bash
# 撤回提交，但保留修改在工作区
git reset --soft HEAD~1

# 现在修改回到了工作区，再用方法一丢弃
git checkout -- app.py
```

##### 情况 B：撤回提交并完全删除修改
```bash
# 硬重置到上一个提交（永久删除修改）
git reset --hard HEAD~1

# 或者重置到特定提交
git reset --hard abc1234  # abc1234 是目标提交的哈希
```

##### 情况 C：只删除 app.py 的修改，保留其他文件的修改
```bash
# 从提交中移除 app.py 的修改
git reset HEAD~1 app.py

# 然后丢弃工作区的修改
git checkout -- app.py

# 重新提交（如果没有其他修改）
git commit -m "Remove app.py changes"
```

---

#### 方法四：如果已经推送到远程

##### 使用 git revert（安全，推荐）
```bash
# 1. 找到包含 app.py 修改的提交哈希
git log --oneline

# 2. 撤销该提交（创建一个新的反向提交）
git revert abc1234  # abc1234 是有问题的提交

# 3. 推送
git push origin branch-name
```

##### 使用 git reset + force push（危险，个人项目可用）
```bash
# 1. 本地回退
git reset --hard HEAD~1

# 2. 强制推送到远程
git push origin branch-name --force-with-lease
```

---

#### 方法五：从另一个分支恢复 app.py

如果你想从 main 分支恢复 app.py：

```bash
# 从 main 分支获取 app.py 覆盖当前分支的
git checkout main -- app.py

# 或者从其他分支
git checkout other-branch -- app.py
```

---

#### 快速参考表

| 修改状态 | 命令 | 说明 |
|---------|------|------|
| **工作区修改（未 add）** | `git checkout -- app.py` | 丢弃修改 |
| **已 add（暂存区）** | `git restore --staged --worktree app.py` | 取消暂存并丢弃 |
| **已 commit，未 push** | `git reset --hard HEAD~1` | 删除最后一次提交 |
| **已 commit，已 push** | `git revert abc1234` | 创建反向提交（安全） |
| **已 commit，已 push（个人）** | `git reset --hard HEAD~1 && git push --force-with-lease` | 强制回退（危险） |

---

#### 完整示例

##### 示例 1：刚修改了 app.py，想放弃
```bash
# 查看状态
$ git status
On branch pr-10-test
Changes not staged for commit:
  modified:   app.py

# 丢弃修改
$ git checkout -- app.py

# 验证
$ git status
On branch pr-10-test
nothing to commit, working tree clean
```

##### 示例 2：已经 add 了，想放弃
```bash
# 查看状态
$ git status
On branch pr-10-test
Changes to be committed:
  modified:   app.py

# 一步恢复
$ git restore --staged --worktree app.py

# 验证
$ git status
On branch pr-10-test
nothing to commit, working tree clean
```

##### 示例 3：已经 commit 了，想删除
```bash
# 查看提交历史
$ git log --oneline
def5678 (HEAD -> pr-10-test) 修改了 app.py  ← 不想要这个提交
abc1234 原始提交

# 删除这个提交（永久删除修改）
$ git reset --hard HEAD~1

# 验证
$ git log --oneline
abc1234 (HEAD -> pr-10-test) 原始提交
```

---

#### 安全提示

##### 如果不确定，先用 stash 备份
```bash
# 保存当前修改到 stash
git stash push -m "保存 app.py 修改以备后用"

# 现在工作区是干净的
git status

# 如果需要恢复修改
git stash pop
```

##### 查看 app.py 的修改内容
```bash
# 查看具体改了什么
git diff app.py

# 查看暂存区的修改
git diff --staged app.py

# 查看提交中的修改
git show HEAD:app.py
```

---

#### 总结

**最简单的情况（未 add）：**
```bash
git checkout -- app.py
```

**已 add 但未 commit：**
```bash
git restore --staged --worktree app.py
```

**已 commit 但未 push：**
```bash
git reset --hard HEAD~1
```

**已 push：**
```bash
git revert <commit-hash>  # 安全方式
```

根据你的修改状态选择合适的方法即可！

## #B16 · 远端有分枝pull/2，怎么在本地把远端的这个分枝删掉？

> 🕒 2026-07-11 22:06 ｜ 来源：[链接 B](https://chat.deepseek.com/share/vb9gzt7w14wkwxmurf) 第 16 轮（消息 ID 31–32） ｜ 主题：分支的创建与删除、丢弃工作区改动、删除文件

**提问**

远端有分枝pull/2，怎么在本地把远端的这个分枝删掉？

**回答**

要删除远端名为 `pull/2` 的分支，需要使用 `git push` 命令配合 `--delete` 选项。

##### 操作命令

在终端中执行以下命令即可：

```bash
git push origin --delete pull/2
```

这条命令会指示 Git 删除远程仓库（`origin`）上的 `pull/2` 分支[citation:1][citation:4][citation:7]。

> **提示**：`--delete` 也可以简写为 `-d`[citation:4][citation:12]。因此，`git push origin -d pull/2` 这条命令同样有效。

##### 注意事项

*   **只删除远程分支**：这个操作仅会删除远程仓库里的分支，你本地的同名分支（如果存在）并不会被影响[citation:1][citation:4]。
*   **谨慎操作**：删除远程分支是一个不可逆的操作。请确保该分支上的代码已合并或不再需要，以免丢失他人的工作成果[citation:7]。

##### 补充：清理本地追踪信息

如果将来又遇到提示本地有远程不存在的分支，可以用以下命令清理一下本地的远程追踪信息：

```bash
git fetch --prune
```
或
```bash
git remote prune origin
```

这个命令会帮你清理掉本地那些对应远程分支已被删除的追踪引用，让 `git branch -a` 的输出更干净[citation:2][citation:7]。

## #B17 · git push origin -d pull/2 error: unable to delete 'pull/2':…

> 🕒 2026-07-11 22:08 ｜ 来源：[链接 B](https://chat.deepseek.com/share/vb9gzt7w14wkwxmurf) 第 17 轮（消息 ID 33–34） ｜ 主题：分支的创建与删除、丢弃工作区改动、删除文件

**提问**

```text
>git push origin -d pull/2
error: unable to delete 'pull/2': remote ref does not exist
error: failed to push some refs to 'https://github.com/wenyuc/math_note'.但是在页面上可以打开pull/2
```

**回答**

这个问题说明 `pull/2` 是一个 **Pull Request**，而不是一个普通的分支。在 GitHub 上，`pull/2` 是 PR 的编号，不是分支名称。

---

#### 理解区别

| 概念 | 示例 | 说明 |
|------|------|------|
| **PR 编号** | `pull/2` | 这是 GitHub 上的 Pull Request 编号，在 URL 中显示 |
| **分支名称** | `pr-10-test` 或 `feature-branch` | 这是实际的 Git 分支名 |

---

#### 查看 PR 对应的真实分支名

##### 方法 1：在 GitHub 页面上查看

1. 打开 PR 页面：`https://github.com/wenyuc/math_note/pull/2`
2. 在 PR 标题下方，你会看到类似：
   ```
   wenyuc wants to merge 3 commits into main from branch-name
   ```
   这里的 `branch-name` 就是真实的远程分支名

##### 方法 2：使用命令行查看

```bash
# 查看所有远程分支
git branch -r

# 查看 PR 对应的分支
git ls-remote origin | grep pull/2
# 或者查看所有引用
git ls-remote origin
```

##### 方法 3：使用 gh 命令（如果安装了）

```bash
gh pr view 2
# 会显示源分支和目标分支信息
```

---

#### 删除 PR 对应的远程分支

##### 步骤 1：找到真实的分支名

从 PR 页面找到源分支名，例如是 `feature-fix` 或 `math_notes-update`。

##### 步骤 2：删除该远程分支

```bash
# 删除远程分支（假设分支名是 feature-fix）
git push origin --delete feature-fix

# 或者
git push origin -d feature-fix
```

---

#### 注意：PR 本身不能通过 git 命令删除

**PR（Pull Request）是 GitHub 平台上的概念**，不是 Git 分支。要删除 PR，需要在 GitHub 页面上操作：

##### 方法 A：在 GitHub 页面上关闭 PR
1. 打开 PR 页面
2. 点击 **"Close pull request"** 按钮
3. 这不会删除分支，只是关闭 PR

##### 方法 B：合并 PR 后自动关闭
- 如果 PR 被合并，GitHub 会自动关闭它
- 你之前合并到 main 的操作应该已经关闭了这个 PR

##### 方法 C：删除源分支后 PR 自动关闭
1. 删除 PR 对应的源分支
2. PR 会被标记为 "Closed"

---

#### 完整操作流程

假设 PR #2 的源分支名是 `feature-math-notes`：

```bash
# 1. 确认 PR 对应的分支名
# 在 GitHub 上查看 PR #2 的页面，找到 "from branch-name"

# 2. 查看远程分支列表
git branch -r
# 输出可能包含：
#   origin/main
#   origin/feature-math-notes
#   origin/pr-10-test

# 3. 删除远程分支
git push origin --delete feature-math-notes

# 4. 验证删除成功
git branch -r
# 应该不再看到 origin/feature-math-notes

# 5. 清理本地远程追踪引用
git remote prune origin
```

---

#### 如果 PR 已经被合并到 main

如果 PR #2 已经被合并，分支可能已经被自动删除了（取决于仓库设置）：

```bash
# 1. 查看远程分支
git branch -r

# 2. 如果分支还在，手动删除
git push origin --delete <branch-name>

# 3. 清理本地缓存
git remote prune origin
```

---

#### 常见错误和解决方法

##### 错误：无法删除 'pull/2'

```
error: unable to delete 'pull/2': remote ref does not exist
```

**原因**：`pull/2` 是 PR 编号，不是分支名

**解决**：找到真实的源分支名，用正确的名称删除

##### 如何找到正确的分支名？

在终端执行：
```bash
# 查看所有远程分支
git branch -r | grep -v HEAD

# 或者查看 PR 的详细信息（需要 gh）
gh pr view 2 --json headRefName
```

输出类似：
```json
{
  "headRefName": "feature-math-notes"
}
```

---

#### 总结

| 你想做的 | 正确操作 |
|---------|---------|
| 删除 PR 对应的远程分支 | 找到真实分支名，执行 `git push origin --delete 真实分支名` |
| 关闭 PR | 在 GitHub 页面点击 "Close pull request" |
| 删除 PR 本身 | 不能通过 git 命令删除，只能在 GitHub 上关闭 |

**关键点**：
- `pull/2` 是 PR 编号，不是分支名
- 远程分支名是类似 `feature-xxx` 或 `pr-xxx` 的名称
- 在 GitHub PR 页面可以找到源分支名
- 使用 `git branch -r` 查看所有远程分支

请先通过 GitHub 页面查看 PR #2 的源分支名，然后用正确的分支名执行删除命令。

## #B20 · 如何在本地创建一个分支？

> 🕒 2026-07-16 14:16 ｜ 来源：[链接 B](https://chat.deepseek.com/share/vb9gzt7w14wkwxmurf) 第 20 轮（消息 ID 39–40） ｜ 主题：分支的创建与删除、丢弃工作区改动、删除文件

**提问**

如何在本地创建一个分支？

**回答**

在 Git 中创建分支非常简单。根据你的需求，有以下几种方式：

---

#### 方法一：创建分支但不切换（最常用）

```bash
# 创建一个新分支（停留在当前分支）
git branch <branch-name>

# 示例
git branch feature-uart
git branch fix-bug
```

---

#### 方法二：创建分支并立即切换（推荐）

```bash
# 创建并切换到新分支
git checkout -b <branch-name>

# 或者使用新的 switch 命令（Git 2.23+）
git switch -c <branch-name>

# 示例
git checkout -b feature-gpio
```

---

#### 方法三：基于特定提交或分支创建

##### 基于某个提交创建分支
```bash
# 基于特定的提交哈希创建分支
git branch <branch-name> <commit-hash>

# 示例
git branch hotfix abc1234
```

##### 基于远程分支创建本地分支
```bash
# 创建本地分支并跟踪远程分支
git checkout -b <local-name> origin/<remote-branch>

# 示例
git checkout -b feature origin/feature-uart
```

---

#### 完整操作示例

```bash
# 1. 查看当前分支
$ git branch
* main

# 2. 创建新分支（不切换）
$ git branch test-branch

# 3. 查看所有分支
$ git branch
* main
  test-branch

# 4. 切换到新分支
$ git checkout test-branch
Switched to branch 'test-branch'

# 5. 或者一步完成（创建并切换）
$ git checkout -b another-branch
Switched to a new branch 'another-branch'
```

---

#### 查看和管理分支

```bash
# 查看本地分支（* 表示当前分支）
git branch

# 查看所有分支（包括远程）
git branch -a

# 查看分支的最新提交
git branch -v

# 查看分支的跟踪关系
git branch -vv
```

---

#### 删除本地分支

```bash
# 删除已合并的分支（安全）
git branch -d <branch-name>

# 强制删除（未合并也会删除）
git branch -D <branch-name>

# 示例
git branch -d test-branch
```

---

#### 分支命名建议

| 分支类型 | 命名格式 | 示例 |
|---------|---------|------|
| 新功能 | `feature/描述` | `feature/gpio-driver` |
| Bug 修复 | `fix/描述` | `fix/uart-baud-rate` |
| 热修复 | `hotfix/描述` | `hotfix/critical-memory-bug` |
| 实验性 | `experiment/描述` | `experiment/new-algorithm` |
| 文档更新 | `docs/描述` | `docs/update-readme` |
| 版本发布 | `release/v版本号` | `release/v1.0.0` |

---

#### 常见场景

##### 场景 1：开发新功能
```bash
# 从 main 创建 feature 分支
git checkout main
git pull origin main  # 确保 main 最新
git checkout -b feature/add-uart-support

# 在分支上工作
# ... 修改代码 ...
git add .
git commit -m "Add UART support"

# 推送到远程
git push -u origin feature/add-uart-support
```

##### 场景 2：修复 Bug
```bash
# 从 main 创建 hotfix 分支
git checkout -b hotfix/fix-crash main
# 或
git checkout main
git checkout -b hotfix/fix-crash

# 修复后合并
git checkout main
git merge hotfix/fix-crash
git branch -d hotfix/fix-crash
```

##### 场景 3：基于远程分支开发
```bash
# 从远程分支创建本地分支
git fetch origin
git checkout -b local-dev origin/remote-branch

# 或使用 track
git branch --track local-dev origin/remote-branch
git checkout local-dev
```

---

#### Git 2.23+ 新命令（推荐使用）

Git 2.23 引入了更直观的 `switch` 和 `restore` 命令：

```bash
# 创建并切换分支
git switch -c <branch-name>

# 切换到已存在的分支
git switch <branch-name>

# 创建基于远程的新分支
git switch -c <branch-name> origin/<remote-branch>
```

---

#### 快速参考

| 操作 | 命令 |
|------|------|
| 创建分支 | `git branch <name>` |
| 创建并切换 | `git checkout -b <name>` |
| 创建并切换（新） | `git switch -c <name>` |
| 基于提交创建 | `git branch <name> <commit>` |
| 基于远程创建 | `git branch <name> origin/<remote>` |
| 切换分支 | `git checkout <name>` |
| 切换分支（新） | `git switch <name>` |
| 查看分支 | `git branch` |
| 查看所有分支 | `git branch -a` |
| 删除分支 | `git branch -d <name>` |
| 强制删除 | `git branch -D <name>` |
| 重命名分支 | `git branch -m <old> <new>` |
| 重命名当前分支 | `git branch -m <new>` |

---
